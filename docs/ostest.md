# 自研嵌入式 RTOS 全面测试规格说明书

> **文档目的**：为自研 RTOS 内核提供系统化、可重复的验证方案，覆盖功能、并发、实时性、稳定性及代码质量等维度，并补充内核边缘行为、上下文原子性、安全防护及深度性能剖析，确保系统在嵌入式环境下的工业级可靠性。

---

## 1. 测试环境与前提准备

- **硬件平台**：目标 MCU 开发板（如 STM32F4 / GD32 / ESP32 等），外接逻辑分析仪或高精度示波器。
- **软件环境**：RTOS 内核源码、硬件抽象层、调试器（J-Link / ST-Link）、串口日志输出。
- **测试框架**：单元测试用 `Unity` / `CppUTest`，硬件在环测试用自动化脚本控制。
- **测试条件**：至少分别在 `-O0`、`-Os`、`-O2` 优化等级下执行全量测试。
- **辅助工具**：逻辑分析仪（测量时间），高精度定时器（DWT），静态分析工具（Cppcheck / PC-lint）。

---

## 8. 代码质量与静态验证

- **单元测试覆盖**：
  - 使用 `Ceedling` + `Unity` 对内核链表、就绪队列操作、定时器链表等底层模块进行单元测试。
  - 分支覆盖率目标 **≥ 90%**，关键模块力争 MC/DC。
- **静态分析扫描**：
  - 启用编译器最高警告选项：`-Wall -Wextra -Werror -Wstrict-prototypes -Wshadow`。
  - 执行 `Cppcheck` 或 `PC-lint` 扫描，检查未初始化变量、内存泄漏、缓冲区溢出、类型转换问题。
  - 可选：遵循 MISRA-C 2012 子集，用工具检查规则符合度。
- **栈使用分析**：
  - 通过静态分析工具（如 `Call Graph` 生成）估算每个任务最大调用栈。
  - 结合运行时水印检测，确保实际使用不超过分配大小的 80%。
- **代码审查清单**：
  - 所有中断中使用的变量声明为 `volatile`。
  - 临界区内无阻塞调用。
  - FromISR 函数结尾正确调用 `portYIELD_FROM_ISR`。
  - 动态内存分配后检查 NULL。

## 9. 编译器、优化与多平台测试

- **多优化等级**：全量回归测试必须在 `-O0`、`-Os`、`-O2`、`-O3` 下通过。
- **不同编译器**：若计划支持 GCC、IAR、ARM Compiler，至少用两种编译器构建并运行压力测试，尤其注意内联汇编和屏障函数的差异。
- **架构移植测试**：若 RTOS 需支持 ARM Cortex-M3/M4/M7 及 RISC-V，应在至少两块不同架构开发板上执行功能与实时性测试。
- **特殊检查**：
  - 高优化下，用 `volatile` 保护的共享标志是否被错误优化。
  - 内嵌汇编的内存屏障是否因优化被重排（可反汇编验证）。
